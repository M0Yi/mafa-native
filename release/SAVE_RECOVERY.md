# 存档与资源恢复

游戏资源缓存与角色存档分开保存。重新选择素材目录不会迁移或清空角色进度。

## 资源检查失败

重新打开资源设置，选择包含 `client2011` 的转换缓存，或重新导入自行准备的原始客户端。程序先检查地图、图像库和声音，再保存资源路径。不要覆盖原始客户端目录。十六周年补充目录可用于已支持的缺图与声音补充，不能保证所有缺失内容均存在。

## 存档加载失败

先退出所有游戏实例，保留数据库及同目录的 `.backup.sqlite`、`-wal`、`-shm` 文件。不要单独删除日志文件，也不要用空数据库覆盖原文件。

- 主库缺失且备份可用：下次打开会先恢复备份。
- 主库损坏且备份可用：原库及其日志会隔离为 `.corrupt-…` 文件，再恢复备份。只能恢复到最近一次成功备份的进度。
- 主库和备份均损坏：拒绝加载并保留文件。
- 主库缺失、没有备份但残留日志：拒绝按新存档初始化，保留文件以便进一步恢复。
- 存档版本不支持：保留原库，不自动降级或重建。

如需报告问题，提供版本、操作步骤和界面错误文字。不要将完整账号数据库、密码或恢复码上传公开 GitHub Issue。

## 已验证范围

隔离测试覆盖主库缺失、主库损坏、主备均损坏、孤立日志、事务提交前/后终止，以及正常退出后的角色恢复。完整断电、COMMIT 进行中终止及各平台实机恢复仍未验收。
